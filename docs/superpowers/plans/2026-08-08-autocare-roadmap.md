## M11 split — why it spans two phases

M11 (Attention Dashboard & Component Visualization, FR-109→FR-117) was added to the SRS after this roadmap was first written. It does not map to one phase, because its two halves have different prerequisites:

- **FR-114 (star ratings) and FR-115 (tap-to-explain)** are a presentation layer over data the VHS engine already produces — band → stars is a display transform, and the explanation sentences are templated from `checklist_points.templates`. Both belong to **Phase 4**, where M-13/M-14 are built; deferring them would mean shipping the score screens twice.
- **FR-109→FR-113 (the "What Needs Attention" dashboard)** aggregates across four sources: `ATTENTION`/`CRITICAL` component statuses (Phase 4), open recommendations (Phase 5), entitlements about to expire unused (Phase 2), and upcoming/overdue services (Phase 3). Recommendations are the last dependency to land, so the dashboard is built in **Phase 5** once every feed exists. Building it earlier would require stubbing feeds and reworking them.

**FR-116 and FR-117 (2D exploded diagram, screens M-39/M-40) are deferred to v1.1 and are deliberately absent from every phase.** They are documented, not built — see `13 Constraints and Risks#Roadmap — visual damage diagram`. The v1.0 tap-to-explain payload (§11.6a) is designed to be exactly what those diagram hotspots will consume later, so deferring costs no rework.

## Sequencing rules

- Phases are strictly ordered; each ends with a demonstrable end-to-end flow on iOS simulator + web + API.
- Wave mapping from `13 Constraints and Risks` §13.2: Phases 0–5 ≈ Wave 1 (the spine), Phase 6 ≈ Wave 2, Phase 7 ≈ Wave 3. Nothing is de-scoped (C-06).
- **Week-1 risk burn-down (R-01):** the Firebase↔NestJS auth exchange is proven inside Phase 0 before any feature work.
- **External lead times started now, not at their phase:** PayMongo merchant application (R-04, needed Phase 2), Apple Developer Program enrollment (needed Phase 0 for TestFlight).
- Open product decisions D-1→D-12 use the documented defaults; all are configuration, so later sign-off never forces rework. **D-12** (who builds the deferred v1.1 diagram assets — in-house or outsourced illustrator) does not gate any v1.0 phase.
- Android stays compiling in CI throughout; device QA deferred to Phase 8 (iOS-first decision).
